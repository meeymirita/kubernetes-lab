оркестратор :: программа, которая запускает, следит и перезапускает контейнеры на многих машинах; Kubernetes — самый известный
кластер :: набор машин (узлов), которыми Kubernetes управляет как одной
control plane :: «мозг» кластера: API-сервер, etcd, scheduler, контроллеры
узел (node) :: одна машина кластера (в kind — Docker-контейнер), на которой запускаются Pod
kubelet :: агент на каждом узле: запускает контейнеры и докладывает о состоянии
API-сервер (apiserver) :: единственная «дверь» в кластер: все команды и все компоненты разговаривают через него
etcd :: хранилище состояния кластера (желаемое и текущее)
scheduler :: выбирает, на каком узле запустить новый Pod
контроллер :: цикл, который сравнивает желаемое состояние с текущим и исправляет расхождение (reconcile)
манифест :: YAML-файл с описанием объекта: `apiVersion`, `kind`, `metadata`, `spec`
декларативный подход :: описываем желаемый результат (`apply`), а не последовательность действий
kubectl :: командная строка для работы с кластером
kind :: Kubernetes in Docker: локальный кластер, где узлы — контейнеры
контекст :: запись в kubeconfig «какой кластер, какой пользователь, какой namespace»; kubectl работает с текущим
kubeconfig :: файл `~/.kube/config` со списком кластеров, пользователей и контекстов
namespace :: «квартира» внутри кластера: имена объектов уникальны в её пределах
label (метка) :: пара ключ-значение на объекте; по меткам объекты находят друг друга
selector :: условие поиска объектов по меткам (так Service находит Pod)
annotation :: пометка на объекте для людей и инструментов; в отличие от меток, по ней не выбирают
Pod :: наименьшая единица запуска: один или несколько контейнеров с общей сетью и томами
контейнер :: запущенный образ внутри Pod
ReplicaSet :: поддерживает заданное число одинаковых Pod; обычно создаётся Deployment’ом
Deployment :: описывает приложение без состояния: число реплик, образ, стратегию обновления
rolling update :: обновление волной: новые Pod поднимаются, старые уходят постепенно, простоя нет
maxSurge / maxUnavailable :: сколько Pod можно добавить сверх нормы / сколько может быть недоступно при обновлении
rollout / rollback :: выкатка новой версии / возврат к предыдущей
StatefulSet :: как Deployment, но с устойчивыми именами и собственными томами (для баз данных)
Job / CronJob :: разовая задача / задача по расписанию
initContainer :: контейнер, который должен завершиться до старта основных
Service :: стабильный адрес и балансировка для набора Pod
ClusterIP / NodePort / LoadBalancer :: типы Service: внутренний адрес / порт на узле / внешний балансировщик облака
headless Service :: Service без общего IP (`clusterIP: None`): DNS отдаёт адреса Pod напрямую
endpoints :: список адресов готовых Pod, на которые Service отправляет трафик
DNS кластера :: имена вида `сервис.namespace.svc.cluster.local`; работает через CoreDNS
CNI :: сетевой плагин кластера; он выдаёт Pod IP и (в некоторых случаях) применяет NetworkPolicy
Ingress :: правила маршрутизации HTTP снаружи на Service (по `Host` и пути)
Ingress Controller :: программа, которая выполняет правила Ingress (у нас Traefik)
IngressClass :: имя контроллера, который должен обслуживать Ingress
IngressRoute :: собственный объект Traefik вместо стандартного Ingress, с богаче возможностями
CRD :: Custom Resource Definition: способ добавить в Kubernetes новый тип объекта
оператор :: контроллер, который умеет эксплуатировать сложное приложение и управляется через CRD
Volume :: каталог, доступный контейнерам Pod; `emptyDir` живёт, пока жив Pod
PersistentVolume (PV) :: кусок хранилища кластера
PersistentVolumeClaim (PVC) :: заявка Pod на хранилище; Kubernetes подбирает или создаёт PV
StorageClass :: «тип диска» и способ его создания; по умолчанию создаёт тома автоматически
accessMode :: режим доступа к тому: `ReadWriteOnce` (один узел), `ReadWriteMany` (много)
ConfigMap :: настройки в виде пар ключ-значение, отдельно от образа
Secret :: то же для чувствительных данных; значения лишь закодированы base64, а не зашифрованы
envFrom :: подключить все пары ConfigMap/Secret как переменные окружения разом
readinessProbe :: проверка «готов ли принимать трафик»; провал убирает Pod из endpoints
livenessProbe :: проверка «жив ли»; провал перезапускает контейнер
startupProbe :: проверка завершения медленного старта
requests / limits :: гарантированный объём ресурсов / потолок; для памяти превышение limits даёт OOMKilled
OOMKilled :: контейнер убит за превышение лимита памяти
QoS-класс :: Guaranteed, Burstable или BestEffort: порядок выселения Pod при нехватке ресурсов
ResourceQuota :: суммарный лимит ресурсов на namespace
LimitRange :: значения по умолчанию и границы для контейнера в namespace
RBAC :: управление правами: кто (subject) что (verb) с чем (resource) может делать
Role / ClusterRole :: набор прав в namespace / на весь кластер
RoleBinding / ClusterRoleBinding :: выдача роли пользователю, группе или ServiceAccount
ServiceAccount :: «учётная запись» Pod для обращения к API кластера
securityContext :: ограничения контейнера: не root, read-only ФС, capabilities, seccomp
Pod Security Standards :: три профиля безопасности (`privileged`, `baseline`, `restricted`), включаются метками namespace
NetworkPolicy :: правила, какие Pod могут разговаривать друг с другом
digest образа :: неизменяемый идентификатор образа `sha256:…`, надёжнее тега
HPA :: Horizontal Pod Autoscaler: меняет число реплик по метрике
VPA :: Vertical Pod Autoscaler: меняет requests/limits Pod
Cluster Autoscaler :: добавляет и убирает узлы кластера по нехватке места
metrics-server :: компонент, отдающий текущее потребление CPU и памяти (для `kubectl top` и HPA)
Prometheus :: система сбора и хранения метрик по pull-модели
Grafana :: построение графиков и дашбордов по метрикам
ServiceMonitor :: объект Prometheus Operator: какие Service опрашивать за метриками
PromQL :: язык запросов Prometheus
Helm :: менеджер пакетов и шаблонизатор для Kubernetes
chart :: пакет Helm: шаблоны манифестов, значения по умолчанию, описание
release :: установленный в кластер экземпляр chart’а с именем и историей ревизий
values :: значения, подставляемые в шаблоны chart’а (`values.yaml`, `-f`, `--set`)
revision (ревизия) :: номер версии релиза в журнале Helm
subchart :: chart, вложенный в другой (зависимость)
umbrella chart :: родительский chart, объединяющий несколько subcharts
named template (`define`) :: именованный шаблон для повторного использования, вызывается через `include`
Kustomize :: настройка манифестов без шаблонов: `base` и накладываемые `overlays`
GitOps :: подход, где желаемое состояние кластера хранится в Git, а контроллер его применяет
Gateway API :: преемник Ingress с разделением ролей и более богатой маршрутизацией
